# 內容過濾策略（彈幕防廣告／防不當內容）

匿名、無帳號、無資料庫、Render 免費方案（0.1 共享 CPU / 512 MB）的限制下，
採用「便宜的規則閘門先擋，昂貴的 ML/LLM 只選擇性補刀」的分層設計。
各大平台（Bilibili、YouTube、Twitch、Discord AutoMod、鬥魚）的共同做法都是
**先跑詞庫／規則層，ML 只在有 CPU、有審核員、有帳號身分時才加**——我們沒有後三者，
所以重壓規則層。

## 分層總覽

| 層 | 內容 | 狀態 | 成本 |
|---|---|---|---|
| 1 | 正規化（NFKC 全形折疊、去零寬、去分隔符、小寫） | ✅ 已實作 `server/filter.js` | ~µs/則 |
| 2 | 結構化廣告／聯絡方式 regex → 靜默丟棄 | ✅ 已實作 `server/filter.js` | ~µs/則 |
| 3 | 記憶體去重＋爆量限速（防洗版/raid，無需 DB） | ⏳ 待做 | 低（TTL Map） |
| 4 | 敏感詞詞庫 DFA（色情／髒話） | 📝 **僅記錄，需先人工審詞** | µs/則（Aho-Corasick） |
| 5 | async LLM moderation 補刀 | 📝 待評估 | 網路延遲，非 CPU |

已在 `GET /stats` 每頻道加上 `blocked` 計數，方便觀測擋下量。

## 第 1 層：正規化（已實作）

只用於「比對」，不動到顯示原文。目的：把規避手法打回原形，讓後面每一層都有效。

- **NFKC**：全形 `ａ／３／＠／ＬＩＮＥ` → 半形，順帶折疊相容字。
- **去零寬字元／雙向控制字元**：常被插進關鍵字中間躲比對。
- **轉小寫**。
- **`compact()`**：再把字元間插入的空白、標點、符號全收掉，破解「賴 ｜ i d」「賺　錢」「ｖ　ｘ」這種拆字。

> 尚未做的正規化（列入第 4 層一起評估）：leetspeak（0→o、1→i）與繁簡折疊（OpenCC）。
> 目前規則層不需要，且 leetspeak 對滿是數字的股價訊息誤判風險高，暫不加。

## 第 2 層：結構化廣告／聯絡方式（已實作）

命中即**靜默丟棄**（silent-drop）：不回訊、不提示。理由——不給對方測試規避的回饋迴路；
發送者端本來就會本地顯示自己的彈幕，等同**影子封鎖**（別人看不到，他也不知道被擋）。

規則（都盡量要求「聯絡意圖」共現以降低誤殺）：

- **網址／短網址**：`http(s)://`、`www.`、`t.me`、`reurl.cc`、`lihi`、`pse.is`、`bit.ly`…、
  以及裸網域（`.com/.net/.xyz/.shop/.vip…`）。
- **LINE／賴**：`加賴／徵賴／私賴／賴id／加line／@line／line+id`。
  單獨的「賴」不擋（避免誤殺姓賴、政治人物名）。
- **微信**：`微信／加微／weixin／wechat／威信／薇信／vx+id`。
- **Telegram**：`telegram／紙飛機／飛機群／@handle`。
- **台灣手機號**：去分隔符後的 `09xxxxxxxx`。
- **高信心詐騙／賭博話術**：`娛樂城／百家樂／博弈／包牌／帶單／保證獲利／穩賺／內線明牌／
  飆股群／加入群組／免費諮詢…`。

**測試**：`server/filter.test.mjs`（`npm test`）。含兩組案例——
「應攔截」（含拆字、全形規避）與「不該誤殺」（台股黑話：乾/靠/幹/韭菜/軋空/當沖/梭哈、
股價數字、姓賴＋無聯絡意圖）。新增規則時務必兩組都補，避免誤殺回歸。

## 第 3 層：去重＋爆量限速（待做）

無需 DB，用有 TTL 的記憶體結構：

- **全域最近訊息 ring buffer**：同一則正規化文字在 T 秒內出現 > N 次 → 丟後續複本（擋複製貼上洗版）。
- **每 IP 上一則比對**：`Map<ip,{lastNorm,count,ts}>`，短 TTL 惰性淘汰；同 IP 連發相同/高相似 → 擋。
- **爆量速度上限**：每 IP 每 10s／60s 上限（例 8/10s、30/60s），疊在現有 0.6s 之上。
- **踩線軟性減速**：踩到去重/爆量就把該 IP 間隔暫時拉長（0.6s→5s，30s 自癒），不需封鎖名單。
- **全域自動慢速**：整體訊息/秒超標（raid）時短暫拉高全域下限。

記憶體以 TTL 淘汰有界，50 字上限下即使高流量也只佔數百 KB。

## 第 4 層：敏感詞詞庫（色情／髒話）— **先審詞，預設不啟用**

> ⚠️ 決策：**不想誤殺**。啟用前我們要自己逐詞審過「哪些可以擋、哪些會誤殺」，
> 先把策略與待審清單記錄下來，之後再決定要不要開、開哪些。

### 技術選型（決定要做時）
- **比對引擎**：`mint-filter`（Aho-Corasick DFA，2 萬詞掃 10 萬字 <35ms；我們 50 字≈微秒級）。
  不要用「每個詞跑一次 regex」的 O(訊息×詞數) 做法。
- **繁簡處理**：`opencc-js`（純 JS 免 node-gyp，Render 免費方案友善）。
  **啟動時**把詞庫一次轉成台灣繁體（`s2tw`），執行期零成本；不要每則訊息轉。
- **開源詞庫（都是簡中優先，需 OpenCC 轉繁，且只取需要的類別）**：
  - `57ing/Sensitive-word`——已分類（色情／暴恐／反動／民生／貪腐），**只取色情＋髒話**。
  - `adlered/DangerousSpamWords`——標榜低誤判，適合匿名 App。
  - `konsheng/Sensitive-lexicon`、`cjh0613/tencent-sensitive-words`——量大，需精簡。
  - **絕不匯入政治類**：會誤殺正常的公司／政策／兩岸財經討論。

### 審詞原則（避免誤殺）
台股／台語黑話大量與髒話同形或諧音，是日常情緒用語而非攻擊，**預設放行**：

- **應放行（不得列入詞庫）**：乾、靠、幹（單字情緒詞）、三小、盤子、韭菜、軋空、
  當沖、梭哈、抱上抱下、畢業、住套房、老師（中性）、割韭菜、破底翻、地板價…
- **可考慮擋（明確色情／人身攻擊）**：明確性交易招攬、露骨性器官詞、明確性招攬話術、
  嚴重人身羞辱字串。這些才進詞庫。
- **處理方式分級**：
  - 明確色情招攬 → 比照第 2 層**靜默丟棄**。
  - 一般髒話（邊界模糊）→ **遮星號或 toast 放行**，不直接擋——一旦誤判仍讓訊息出去。
- **審詞流程**：候選詞先各自標註 允許/遮罩/擋 三態 → 用第 2 層那種「應攔截 / 不該誤殺」
  雙向測試集驗過 → 才進 production；預設 flag `MODERATION_WORDLIST=off`。

## 第 5 層：async LLM moderation（待評估）

- **OpenAI `omni-moderation-latest`**：免費、不計用量、<100ms、中文表現強。
- **用法（守住 CPU 預算）**：**絕不**每則同步阻塞呼叫。
  - 樂觀放行後 async 檢查，flag 就發 retract 事件收回彈幕（反正彈幕無狀態）。
  - 或只對「前面各層覺得可疑但沒攔到」的少數殘量呼叫。
- 屬**外部網路呼叫**、幾乎不吃本機 CPU；代價是延遲與第三方相依。
  **API 掛掉要 fail-open**（前面規則層已擋掉明顯的）。
- 需要 OpenAI API key；多一個外部相依，故列為選配、非地基。
