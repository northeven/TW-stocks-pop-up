# 內容過濾策略（彈幕防廣告／防不當內容）

匿名、無帳號、無資料庫、Render 免費方案（0.1 共享 CPU / 512 MB）的限制下，
採用「便宜的規則閘門先擋，昂貴的 ML/LLM 只選擇性補刀」的分層設計。
各大平台（Bilibili、YouTube、Twitch、Discord AutoMod、鬥魚）的共同做法都是
**先跑詞庫／規則層，ML 只在有 CPU、有審核員、有帳號身分時才加**——我們沒有後三者，
所以重壓規則層。

## 分層總覽

| 層 | 內容 | 狀態 | 成本 |
|---|---|---|---|
| 1 | 正規化（NFKC 全形折疊、去零寬、去分隔符、小寫） | ✅ 已實作 `server/filter.js` | ~µs/則 |
| 2 | 結構化廣告／聯絡方式 regex → 靜默丟棄 | ✅ 已實作 `server/filter.js` | ~µs/則 |
| 3 | 洗同句偵測 → 冷靜 30 秒（記憶體 TTL，無需 DB） | ✅ 已實作 `server/index.js` | 低（TTL Map） |
| 4 | 露骨色情／性招攬詞（已審 FP 的精簡清單） | ✅ 已實作 `server/filter.js` | µs/則 |
| 5 | async LLM moderation 補刀 | 📝 待評估 | 網路延遲，非 CPU |

已在 `GET /stats` 每頻道加上 `blocked` 計數（含廣告過濾＋洗同句冷靜期擋下量），方便觀測。

**實測 CPU**：`screen()` 每則 ≈ 1.3 µs、單核滿速 ≈ 75 萬則/秒；Render 0.1 CPU 約 1/10 仍有
~7.5 萬則/秒餘裕。過濾開銷可忽略，真正的成本是廣播扇出（500 人房）。

## 第 1 層：正規化（已實作）

只用於「比對」，不動到顯示原文。目的：把規避手法打回原形，讓後面每一層都有效。

- **NFKC**：全形 `ａ／３／＠／ＬＩＮＥ` → 半形，順帶折疊相容字。
- **去零寬字元／雙向控制字元**：常被插進關鍵字中間躲比對。
- **轉小寫**。
- **`compact()`**：再把字元間插入的空白、標點、符號全收掉，破解「賴 ｜ i d」「賺　錢」「ｖ　ｘ」這種拆字。

> 尚未做的正規化（列入第 4 層一起評估）：leetspeak（0→o、1→i）與繁簡折疊（OpenCC）。
> 目前規則層不需要，且 leetspeak 對滿是數字的股價訊息誤判風險高，暫不加。

## 第 2 層：結構化廣告／聯絡方式（已實作）

命中即**靜默丟棄**（silent-drop）：不回訊、不提示。理由——不給對方測試規避的回饋迴路；
發送者端本來就會本地顯示自己的彈幕，等同**影子封鎖**（別人看不到，他也不知道被擋）。

規則（都盡量要求「聯絡意圖」共現以降低誤殺）：

- **網址／短網址**：`http(s)://`、`www.`、`t.me`、`reurl.cc`、`lihi`、`pse.is`、`bit.ly`…、
  以及裸網域（`.com/.net/.xyz/.shop/.vip…`）。
- **LINE／賴**：`加賴／徵賴／私賴／賴id／加line／@line／line+id`。
  單獨的「賴」不擋（避免誤殺姓賴、政治人物名）。
- **微信**：`微信／加微／weixin／wechat／威信／薇信／vx+id`。
- **Telegram**：`telegram／紙飛機／飛機群／@handle`。
- **台灣手機號**：去分隔符後的 `09xxxxxxxx`。
- **高信心詐騙／賭博話術**：`娛樂城／百家樂／博弈／包牌／帶單／保證獲利／穩賺／內線明牌／
  飆股群／加入群組／免費諮詢…`。

**測試**：`server/filter.test.mjs`（`npm test`）。含兩組案例——
「應攔截」（含拆字、全形規避）與「不該誤殺」（台股黑話：乾/靠/幹/韭菜/軋空/當沖/梭哈、
股價數字、姓賴＋無聯絡意圖）。新增規則時務必兩組都補，避免誤殺回歸。

## 第 3 層：洗同句偵測（已實作，`server/index.js`）

規則（與使用者議定）：**10 秒內同一句超過 5 次 → 該 IP 冷靜 30 秒**。冷靜期內一律擋、回 toast。

- 以**正規化後的句子**（`normalize()`）比對——全形／拆字的同一句也算同一句。
- 資料結構：`ipDup: Map<ip, { norm, hits:[時間戳], until, ts }>`，`hits` 只保留 10 秒內的時間戳。
- 跨 socket 有效：`ipDup` 以 IP 為鍵，開多分頁洗同句一樣被抓（同 IP）。
- 記憶體有界：與 `ipLastSent` 共用每 60 秒的 sweep，淘汰過期 IP，50 字上限下高流量也只數百 KB。
- 與既有限流的關係：1.2s 同 IP 節流＋令牌桶已把單人壓到 ~5 則/10s；本層主要收「開多分頁繞過
  單一連線」與「持續洗同句」，踩線就 30 秒硬冷靜。

> 未實作（列為未來選項，目前不需要）：全域 ring buffer（跨 IP 同句 raid 偵測）、
> 全域自動慢速。單一 IP 的洗版已由本層＋節流涵蓋。

## 第 4 層：露骨色情／性招攬詞（已實作，`server/filter.js`）

> 決策：**不想誤殺**，所以不整包匯入簡中大詞庫，而是**自己逐詞審過 FP** 的精簡清單。
> 中文是子字串比對，露骨詞很容易被財經／日常詞夾出誤判——寧可漏也不要誤殺。

### 已收詞（命中即靜默丟棄，只比對 `norm`）
`約炮、約砲、外送茶、賣淫、嫖妓、嫖娼、可外約、顏射、插穴、裸聊、打手槍、應召站、
幼交、戀童、迷姦、輪姦、強姦、一夜情（後面不接 勢／懷／況）`

只比對 `norm`（保留分隔符）、刻意不比對 `compact`：避免「外送 茶飲 → 外送茶」這種
分隔符收合造成的誤殺。代價是「自 慰」這種空格拆字會漏——可接受（露骨騷擾很少拆字，
色情廣告則已被第 2 層的網址／聯絡方式攔掉）。

### 待審清單（**刻意不收**，附誤殺母字串；要收需個別上下文界定）
| 詞 | 會誤殺 | 若要收的做法 |
|---|---|---|
| 口爆 | 缺**口爆**量 | lookbehind `(?<!缺口)` 不夠乾淨，暫不收 |
| 性交易／性服務 | 彈**性**、理**性** + 交易/服務 | 需排除 彈/理/感/個/慣… 前綴，太脆弱 |
| 援交 | 支**援交**流 | `(?<!支援)`；但還有 後援/聲援… |
| 群交 | 客**群交**易、族**群交**流 | 同上，前綴太多 |
| 內射 | 禁區**內射**門 | 運動語境 |
| 做愛 | **做愛**心做公益 | `做愛(?!心)`，可考慮 |
| 肉棒 | 蟹**肉棒**（食物） | `(?<!蟹)`，還有 雞肉棒… |
| 性侵 | 個**性侵**略性 | 前綴太多 |
| 自慰 | 獨**自慰**問、各**自慰**勞 | 前綴太多 |
| 援妹 | 支**援妹**妹 | 低價值，不收 |
| 屌 | 好**屌**（讚美！） | **絕不收** |
| 機掰／雞掰／打炮／騷貨 | 台語日常髒話／情緒 | 建議放行，或未來走「遮星號」而非丟棄 |

### 台股／台語黑話白名單（**永遠放行**，測試已涵蓋）
乾、靠、幹、三小、盤子、韭菜、軋空、當沖、梭哈、割韭菜、住套房、畢業、老師…

### 若未來要擴充成大詞庫
- 引擎換 `mint-filter`（Aho-Corasick DFA），繁簡用 `opencc-js`（純 JS 免編譯）啟動時轉一次。
- 詞庫來源 `57ing/Sensitive-word`（只取色情）、`adlered/DangerousSpamWords`（低 FP）；
  **絕不匯政治類**。每個詞都要過 `filter.test.mjs` 的「應攔截／不該誤殺」雙向測試才進 production。
- 邊界模糊的髒話改走「遮星號放行」而非丟棄（需把 norm 位置映射回原文，較麻煩，故目前只做丟棄層）。

## 第 5 層：async LLM moderation（待評估）

- **OpenAI `omni-moderation-latest`**：免費、不計用量、<100ms、中文表現強。
- **用法（守住 CPU 預算）**：**絕不**每則同步阻塞呼叫。
  - 樂觀放行後 async 檢查，flag 就發 retract 事件收回彈幕（反正彈幕無狀態）。
  - 或只對「前面各層覺得可疑但沒攔到」的少數殘量呼叫。
- 屬**外部網路呼叫**、幾乎不吃本機 CPU；代價是延遲與第三方相依。
  **API 掛掉要 fail-open**（前面規則層已擋掉明顯的）。
- 需要 OpenAI API key；多一個外部相依，故列為選配、非地基。

## 實作順序建議

1. ✅ 第 1 層 正規化（倍增器，最先做）
2. ✅ 第 2 層 網址／聯絡方式靜默丟棄（防廣告 CP 值最高）
3. ✅ 第 3 層 洗同句偵測 → 冷靜 30 秒（無新依賴）
4. ✅ 第 4 層 露骨色情精簡詞庫（**已審 FP**）
5. 📝 第 5 層 async LLM（選配補刀）
